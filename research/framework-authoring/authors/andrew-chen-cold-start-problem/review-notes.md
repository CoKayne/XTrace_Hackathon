# The Cold Start Problem Public Framework Pack — Review Notes

Status: `draft / unpublished`

## Core role

This pack converts a network-effect story into operating evidence and
stage-specific underwriting. It does not automatically award a moat premium.

## Required sequence

1. Prove the product has a defined participant interaction.
2. Define the atomic-network boundary.
3. Identify the hard side.
4. Measure local density, successful interactions, and retention.
5. Establish repeatability across atomic networks.
6. Separate acquisition, engagement, and economic effects.
7. Audit subsidy, ceiling, quality, multi-homing, and competition.
8. Pass only evidenced driver changes to deterministic valuation.

## Important product interfaces

- Company profile: participant roles, network type, atomic unit, geography.
- Evidence Pack: node/edge activity, match success, cohorts, retention,
  contribution distribution, incentives, and unit economics.
- Market events: can change acquisition costs, supply, regulation, or
  competitor behavior but cannot prove density.
- Deterministic services: cohorts, density, liquidity, growth accounting,
  subsidy, and valuation.

## Main conflicts preserved

- Growth can be viral without increasing user value.
- Global scale can coexist with weak local density.
- More users can improve liquidity while degrading quality.
- A data advantage can exist without direct network effects.
- The hard side can create value while capturing enough power to weaken
  platform economics.
